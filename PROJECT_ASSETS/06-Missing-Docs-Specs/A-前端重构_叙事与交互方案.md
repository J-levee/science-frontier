# A. 缺失文档规格：前端重构 · 叙事与交互方案（含荣誉星图正式设计）

## 背景 / 为什么缺
用户已**明确要求重构前端**，原话："现在的设计交互感弱、讲不好故事，不能很好地把我们的故事陈述出来"。
当前 `04-Frontend-Site/index.html` 是零依赖单文件，P1 荣誉星图仅为 `P1 荣誉星图 TEMP` 临时板块。
重构仅停留在概念讨论（见 `01-Product-Narrative-Visual/`、`视觉叙事规划_三体诺奖.md`），**从未落地为可实施的方案文档**。

## 目标读者
- 重构实施 Agent（视觉叙事 + 前端架构）
- 用户（用于签批，遵循协作铁律：生产改动前需评审文档 + 签批）

## 必须包含的章节
1. **体验现状诊断**：具体指出"讲不好故事"发生在哪一段——首页无钩子？进问题详情后叙事断裂？奖项板块孤零零接不上主线？附当前截图/录屏佐证。
2. **故事弧设计**：现状（已知边界）→ 冲突（未知之浩瀚）→ 解决（人类用奖项/探索照亮未知）如何落到滚动节奏与视图切换里。
3. **交互骨架**：从"翻卡片"升级成什么——星系可缩放探索 / 获奖者↔问题双向链接 / 滚动驱动时间线 / 手势或光标跟随。给出信息架构图。
4. **视觉语言**：保留 5 色语义 + 星空（见 README §1、§5.4）；重做首屏钩子与移动端叙事；定义动效原则（克制、不喧宾夺主）。
5. **荣誉星图正式设计**（替换 TEMP）：节点=获奖者"灯塔"，按三星系着色；hover 显获奖理由；点击进详情；与 109 问题建立关联（获奖者→其领域问题）。给出组件规格与数据绑定方式（读 `awards-data.js`）。
6. **技术选型决策**：是否维持**零依赖单文件 + 离线优先**（推荐维持，除非用户拍板引入 Vite/框架）；若引入构建链，说明代价与收益。
7. **实施分阶段**：先方案评审 → 用户签批 → 增量替换，保留叙事核心（边界线/星系/水滴/5色/溯源锚/知识星座）。
8. **验收标准**：见下。

## 验收标准
- 故事弧可用一句话清晰描述，且首屏 5 秒内传达项目定位。
- 奖项与问题双向可达（从问题能找到相关获奖者，反之亦然）。
- 移动端叙事可用（响应式 + 触摸）。
- 不破坏 100% 溯源锚与 5 色语义。
- 用户签批通过。
