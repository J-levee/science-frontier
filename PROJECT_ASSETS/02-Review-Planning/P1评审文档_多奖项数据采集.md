## 2. 数据源调研结论（办公室电脑实测，2026-07-31）

| 数据源 | 测试结果 | 结论 |
|--------|----------|------|
| 诺奖 v2 API `api.nobelprize.org/2.1/laureates`（带 UA） | **HTTP 200**，返回正常 | ✅ **自动主源**（诺奖物理/化学/医学全量） |
| 诺奖 v1 CSV `api.nobelprize.org/v1/laureate.csv` | HTTP 403 | 弃用 |
| Wikidata SPARQL `query.wikidata.org` | **TLS 握手超时（GFW 阻断）** | ❌ 不能作统一源 |
| 其他奖项官网（Fields/Abel/Turing/Shaw/Kavli…） | 未实测，GFW 下部分不可达 | 策展起步，自动化采集列 P2 |

**关键约束**：办公室电脑（数据源+编排器）有 GFW。诺奖 API 可达（带 UA 即可），Wikidata 被墙，其他奖项无统一 API。因此采集必须**离线优先**——一次性采集落地本地文件，运行时零网络依赖（与 P0 内联 D3 一致）。

## 3. 采集奖项清单（科学边界相关前沿奖项 → 三体星系映射）

筛选原则：只收与「科学边界」10 领域强相关的 Apex/Elite 层奖项；不收文学奖、和平奖、经济学奖（非科学边界）。

- 诺贝尔化学奖 ★自动（化学 ≈ 物+生 交叉，归物理星）

- Breakthrough Prize 基础物理
- Gruber 宇宙学奖

- 京都奖基础科学

### 生命星系（存在与演化）
- 诺贝尔生理学或医学奖 ★自动
- Lasker 奖（基础 / 临床医学）
- 邵逸夫生命科学与医学奖
- Breakthrough Prize 生命科学
- Gairdner 国际奖

### 计算星系（形式与智能）
- 图灵奖（ACM）★自动候选（有官方数据源）

> 精选约 12–15 个奖项，避免过杂。星标「★自动」= 有结构化官方源可脚本拉取；其余 P1 先策展精选代表性获奖者，自动化采集列 P2（需解决 GFW）。

## 4. 采集策略

- **诺奖（物理/化学/医学）**：脚本自动拉 v2 API（带 UA），全量历史获奖者。
- **其他奖项**：P1 采用**策展精选**起步——基于官方名单人工整理为结构化数据（保证质量 + 离线），自动化爬虫/镜像采集列 P2。
- **离线优先**：所有数据落本地 `awards-data.js`，内联进 `index.html`，运行时零网络依赖。

## 7. 影响面与风险

- **影响面**：仅 `index.html` 单文件 + 新增独立脚本/数据文件。不动 P0 已有星系/水滴逻辑、不动数据 `window.DATA`、不动其他视图。
- **风险与缓解**：
  - GFW：诺奖可达；其他策展不依赖网络 → 无阻塞 ✅
  - 数据量：诺奖约 1000+ 人，全量内联会显著增大 `index.html`；**建议按科学边界相关筛选**（物理/化学/医学全收，其他奖项精选 Top 获奖者），控制体积
  - 内联体积：若 `awards-data.js` 过大，改为同目录外链（但 `file://` 直开有之前的加载问题）→ 优先内联；若超标则用同目录外链 + 预览服务器打开
  - 字段质量：策展数据人工校验，避免错漏
- **回退**：`index.html.bak` 已备份（P0 留）；采集脚本独立；`awards` 数组可整体回退到 `[]`。
