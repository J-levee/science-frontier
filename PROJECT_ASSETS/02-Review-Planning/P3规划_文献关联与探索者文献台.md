## 1. 愿景定位

用户原话：「后续还要做和文献的数据关联，包括诺奖等前沿研究者和文献的关联、研究方向与文献的关联；应用上，为准备研究某个方向的探索者准备文献检索工具，提供参考文献（文件库内和全球权威其他来源）。」

三层含义：
1. **研究者 ↔ 文献**：诺奖/前沿研究者的代表作、关键论文，连进星系。
2. **研究方向 ↔ 文献**：每个领域/前沿问题关联其奠基性、里程碑、综述文献。
3. **应用层**：探索者选定一个方向 → 提供参考文献（内部文件库 + 全球权威来源）。

**叙事钩子（复用 P0 的 Story Spine）**：「每篇文献是一束光，连接两个问题、一位探索者。」——文献节点让关联网络从「179 条问题连线」升级为真正的**知识星座**。

## 2. 数据架构：星系知识图四层

```
应用层    🔭 探索者文献台（按方向检索/提供参考文献）
   │
文献层    literatures[]  —— 论文/图书节点（按 star 着色，按引用量定大小）
   │  （关联边：问题↔文献 / 研究者↔文献 / 方向↔文献）
实体层    109 前沿问题 · 诺奖/奖项(P1) · 研究者(P2) · 研究方向/领域
```

- **实体层**（在建/已建）：3 恒星 7 行星 / 109 问题 / awards+laureates(P1) / researchers(P2)
- **文献层（新）**：`literatures[]` 数组
- **关联边（新）**：由 `linked_problems` / `linked_laureates` / `linked_directions` 派生（与 awards 的 `links` 同构）
- **应用层（新）**：探索者文献台

## 3. literatures 数据 Schema（与 awards 同构）

```js
const literatures = [
  {
    id: "lit-2023-xyz",            // 唯一标识
    title: "Attosecond pulses...", // 题名
    authors: ["A. L'Huillier", "..."],
    year: 2023,
    type: "paper",                 // paper | book | review
    doi: "10.xxxx/...",            // 可选
    star: "physics",               // 三体映射（与 awards 一致）
    domain: "物理",                // 映射到 10 领域之一
    source: "internal",            // internal(文件库内) | external(全球权威)
    sourceName: "F盘中文图书",      // 具体来源标识
    url: "https://...",            // 可选可点击
    abstract: "中文摘要...",
    citations: 1200,               // 引用量（定大小用）
    isLandmark: true,              // 是否奠基/里程碑文献
    linked_problems: ["p-001"],    // 关联 109 问题 id
    linked_laureates: ["nobel-phys-2023"], // 关联 awards id
    linked_directions: ["物理"],   // 关联研究方向
  },
  // ...
];
```

## 4. 两条落地轨道（关键架构决策）

静态 HTML 单文件**无法在运行时实时访问全球来源**（GFW + CORS 双重阻断），因此文献能力必须分两条轨道：

### 轨道 A · 离线策展（进 HTML）
- 每问题 / 诺奖者的**奠基/里程碑/综述**文献，人工策展 + 预采集，内联成 `literatures-data.js`。
- 零 GFW 依赖，与 P0 内联 D3、P1 内联 awards 完全一致。
- 承载「问题详情页·奠基文献区块」「诺奖/研究者档案·代表作区块」。

### 轨道 B · 实时检索（交给 SmartLib）
- 探索者文献台的**点对点实时检索**，调你已有的 SmartLib 文献能力，**不要在静态 HTML 里重造轮子 / 硬刚 GFW**：
  - `global-biblio-base`：12 亿文献元数据 + 8000 万中文期刊全文
  - `book-searcher`：F 盘中文 370 万 + 外文 770 万 CSV
  - `literature-search`：检索入口
  - `smartlib-citation-checker`：参考文献真实性核查
- 集成方式：文献台「实时检索」按钮 → 跳转/调用 SmartLib 对话式检索（SCF 服务端，天然绕开 GFW）。

## 5. 复用你已有的文献资产（避免重建）

| 资产 | 能力 | 在 P3 的角色 |
|------|------|------------|
| global-biblio-base | 12 亿文献 + 8000 万中文期刊全文 | 轨道 B 全球权威来源主力 |
| book-searcher | F 盘中文/外文图书 CSV | 轨道 B「文件库内」主力 |
| literature-search | 检索入口 | 轨道 B 触发入口 |
| smartlib-citation-checker | 参考文献核查 | 验证文献真实性（防 AI 幻觉） |
| 新知库 / 学术知识库 skills | 本地库检索 | 内部文件库补充 |

> 结论：**文献引擎不必在 Science Frontier 重建**。Science Frontier 只负责「实体 ↔ 文献」的关联数据（轨道 A 策展）+ 一个指向 SmartLib 的检索入口（轨道 B）。
